# Selectable Transcribe trigger: approved specification

Human requested an adjustable Transcribe capture button and specifically authorized overriding normal Print Screen during Transcribe. Follow-up clarification: "when single pressed (press/relase) take a screenshot, when print screen is hold enable selecting (like it normaly works with mmb)". Human also confirmed exclusive selection: "mmb / printscreen is selectable so if print screen is selected mmb shouldnt work and vice versa". Target window is under pointer on any monitor; existing starting-monitor clipping for rectangles remains. No extra click/arming step and no long-press timer.

## Acceptance criteria
P01 Add a persisted, validated Transcribe capture-trigger choice: Middle mouse (legacy/default value 0) or Print Screen. Missing property in old settings preserves MMB. Invalid enum is rejected consistently with existing settings validation. Both WPF and WinForms settings show the same choices and save/cancel correctly. All Settings <-> PanelOptions <-> TrayPanel mappings preserve it, including unrelated mode/setting changes.
P02 Selected trigger is exclusive and frozen at session start. MMB mode retains current click/drag behavior; Print Screen follows its normal path and is not consumed by Transcribe. Print Screen mode leaves MMB and ordinary left/right/wheel/keyboard input on their normal paths; MMB must not capture.
P03 Bare Print Screen press snapshots pointer position, target window/title and starting monitor. Release without a drag captures that window; pointer movement while held uses the existing drag threshold/overlay and monitor clipping, release captures the rectangle. No extra mouse click, timeout or foreground activation. Target selection is unrestricted across monitors. Repeats cannot duplicate/restart captures. Ignore unmatched release (including session start while a key was already held).
P04 Print Screen mode suppresses captured Print Screen down/up (including repeats) so the normal OS screenshot/snipping action cannot replace the screenshot batch clipboard. Restrict suppression to active Transcribe input lifetime. Modified Print Screen combinations must continue through normal handling, particularly existing Ctrl+Alt+Print Screen start/stop shortcut; if an initially captured key is held while modifiers change, retain ownership through its release. No OS setting/registry remapping. Fn keys must deliver VK_SNAPSHOT to work; no claim of universal firmware behavior.
P05 Escape cancels an in-progress Print Screen selection without capturing and consumes its cancellation press/release so the same press does not invoke host double-Esc stop. Overlay hides and no stale release may complete the canceled gesture. Undo/Next Batch/close discard pending gestures as appropriate; asynchronous callbacks cannot add canceled captures. Dispose/Stop release hooks/resources on all paths. If session closes during a held Print Screen, prevent that owned gesture from later becoming a Windows screenshot or stale capture; keep any necessary paired-release cleanup bounded to the owned gesture, not future Print Screen presses. Document/test actual strategy and limits rather than claim native verification without evidence.
P06 Panel instructions reflect selected trigger. Existing batch, limit, ZIP, X/Stop, tray restore, placement, clipboard lifetime/cleanup, Clear and video behavior remain unchanged. Normal Print Screen behavior remains outside Transcribe and in MMB mode. No side-button/right-hold/modifier capture options in this task.
P07 Behavioral RED before implementation and GREEN after, covering exclusivity, tap/drag under-pointer start snapshot, threshold/clipping including negative monitor coordinates, repeats/unmatched releases, modified Print Screen passthrough, cancellation, teardown and held-key boundaries. Meaningful settings default/persistence/UI save/cancel coverage. Run existing Debug/Release/core/settings/clipboard/Python checks. Native key dispatch/Windows Snipping compatibility requires interactive validation; injected tests are not proof of OS-level suppression. Preserve previously deferred mixed-DPI/multi-monitor tests explicitly.

## Design and delivery
Reuse existing TranscribeGesture and normalize selected physical trigger into its existing pointer down/move/up contract. Separate testable routing/ownership policy from low-level native hooks; use VK_SNAPSHOT=0x2C and GetCursorPos for keyboard positions. Avoid capture/encoding inside hooks. Do not alter recording shortcut semantics or video pipeline. Small injectable boundaries permit behavioral tests without replacing the actual clipboard or injecting keys into unrelated apps.

Sources: Microsoft virtual-key codes https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-tvtt/261ddfb0-ce10-4380-9b7a-4b50f482b8ec and LowLevelKeyboardProc https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/ms644985(v=vs.85) : return nonzero for handled input, chain unhandled input. Keyboard repeat/paired ownership are application responsibilities.
